# 签到模块执行

`SignInExecutor` 为插件提供失败隔离、有限重试和安全错误文案。社区、游戏和各游戏角色分别执行，使用 `RunModuleAsync` 或 `RunModulesAsync` 收集结果后，由插件合并成一次通知。同一账号的模块顺序运行，避免并发使用 scoped DbContext；某个模块失败不阻止后续模块，宿主取消则立即终止。

`ExecuteWithRetryAsync` 默认在首次失败后重试 3 次，共最多 4 次，等待 1、2、3 秒。重试网络中断、请求超时、HTTP 408/429/5xx，以及插件明确识别的 `SignInTransientException`。凭据失效、验证码、配置缺失等业务终态不重试。耗尽重试的通知保留实际次数和日志关联编号。

重试边界应为单个 HTTP 请求（每次重新构造 request），或“先查状态再签到”的单角色操作。已经成功的社区任务和其他角色不应重新执行。签到 POST 丢失响应时应重新确认今日状态，或处理平台明确的“今日已签到”返回，避免把已完成签到误报失败。

生产环境注入 `SignInExecutor`；测试可将 `retryDelay` 设为零，验证请求次数和最终通知，不发送真实签到请求。
